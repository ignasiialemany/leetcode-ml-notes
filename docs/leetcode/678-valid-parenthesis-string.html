678. Valid Parenthesis String

Greedy interval of possible open counts [lo, hi]

Insight

Each * can be (, ) or empty, so there are up to \(3^k\) readings — but you never need to know which reading. Track only the set of balances (open − close) that some reading can be at after each prefix, ignoring any reading that ever went negative. That set is always a contiguous interval \([lo, hi]\). ( shifts it up, ) shifts it down, * widens it by one on each side. Clamp \(lo\) at 0 (negative balances are dead paths), fail the moment \(hi < 0\), and accept iff \(lo = 0\) at the end.

The band on (*()*)**

The blue line is "every star is (" (the most opens you could have), the orange line is "every star is ) unless that would go negative" (the fewest). Thin grey lines are concrete star readings that stay \(\ge 0\) — every one of them lives inside the band, and every integer in the band is hit by some reading. Red dashes are where \(lo - 1\) would dip below zero: that reading has more ) than ( so far and can never recover, so we just drop it and clamp.

Update rules: $$\texttt{(}:\ [lo,hi]\to[lo+1,\,hi+1]\qquad \texttt{)}:\ [lo-1,\,hi-1]\qquad \texttt{*}:\ [lo-1,\,hi+1]$$ then \(lo \leftarrow \max(lo, 0)\). End: valid \(\iff 0 \in [lo, hi] \iff lo = 0\).

Why two numbers are enough: the DP table collapses

The honest DP is a boolean table \(\text{reach}[i][b]\) = "some reading of the first \(i\) characters stays \(\ge 0\) and ends at balance \(b\)":

$$\text{reach}[i+1][b] = \begin{cases} \text{reach}[i][b-1] & s_i = \texttt{(}\\ \text{reach}[i][b+1] & s_i = \texttt{)}\\ \text{reach}[i][b-1] \lor \text{reach}[i][b] \lor \text{reach}[i][b+1] & s_i = \texttt{*}\end{cases}\qquad b \ge 0$$

That is \(O(n^2)\) cells. But look at any column: the ✓ cells form one gap-free run. Shifting a run keeps it a run; widening by ±1 (and taking the union with itself) keeps it a run; cutting off \(b < 0\) keeps it a run. By induction every column is exactly \([lo, hi]\), so the table is fully described by its two endpoints — \(O(1)\) state.

The orange box per column is \([lo, hi]\); it covers exactly the reachable cells. Answer \(=\text{reach}[n][0]\), i.e. \(lo = 0\).

The two ways to fail

\(hi < 0\) mid-scan: even reading every star as ( there are more closes than opens — no later character can fix a prefix, so return immediately. \(lo > 0\) at the end: even reading every star as ) some open is left unmatched.

Left: (*))) — the fifth character pushes \(hi\) to −1. Right: ((* — the band ends at \([1, 3]\), not touching 0.

Alternative: two passes

Same bounds, split up. Left→right, treat every * as (: if the balance ever goes negative, too many closes (\(hi < 0\)). Right→left, treat every * as ) and count closes vs opens: if it ever goes negative, too many opens (the mirror of \(lo > 0\)). Pass both → valid. Also \(O(n)\) / \(O(1)\), but the one-pass interval makes the "set of reachable balances" picture explicit.

Code

class Solution:
    def checkValidString(self, s: str) -> bool:
        lo = hi = 0
        for c in s:
            if c == '(':
                lo += 1; hi += 1
            elif c == ')':
                lo -= 1; hi -= 1
            else:
                lo -= 1; hi += 1
            if hi < 0:
                return False
            lo = max(lo, 0)
        return lo == 0

Complexity

One pass with two integers: \(O(n)\) time, \(O(1)\) space — versus \(O(n^2)\) time/space for the \(\text{reach}[i][b]\) table and \(O(3^k)\) for brute-forcing the stars.
