301. Remove Invalid Parentheses

Count min removals first, then keep/delete backtracking with exact budgets

Insight

Two questions hide in this problem: how many characters to delete, and which ones. Answer the first exactly before searching, and the search shrinks to only strings that are already the right length.

  • How many: run the clamped counter from 921. Every ) that arrives when the counter is 0 is an orphan (\(r\) of them), and whatever is still open at the end is \(l\) leftover (. Deleting is the mirror image of inserting: an orphan ) can be fixed by deleting a ) instead of inserting a (. So the minimum is exactly \(l + r\), and we know that it means \(l\) opens and \(r\) closes.
  • Which: walk the string with a running balance. At each paren you either keep it or delete it, and deleting is only allowed while that bracket type still has budget. Cut a branch as soon as the balance goes negative (an orphan ) you can never repair) or exceeds the characters left (too many opens to close). A leaf counts only if both budgets hit 0 and the balance ends at 0.
$$\underbrace{(l,\ r)}_{\text{one scan}} \;\Rightarrow\; \text{DFS over } \binom{\#\texttt{(}}{l}\binom{\#\texttt{)}}{r} \text{ deletion patterns at most, pruned by } 0 \le \text{bal} \le n - i$$

Different deletion patterns can give the same string, e.g. deleting either of two neighbouring )), so the leaves go into a set. Every string in the set is automatically minimal because every branch spent exactly \(l + r\) deletions.

Step 1: the balance scan sets the budget

Scan ()())() with the clamped counter. It touches 0 after ()(), and the next ) at index 4 has nothing to match: that is the one orphan, so \(r = 1\). The counter ends at 0, so \(l = 0\). Exactly one ) must go, and no (.

The dashed raw balance dips to \(-1\) at index 4. To lift that dip, a ) at or before index 4 has to go (indices 1, 3, 4, shaded). Deleting the ) at index 6 can't help because it comes after the dip. Min deletions \(= l + r = 0 + 1 = 1\).

Step 2: keep/delete DFS with exact budgets

Each node is the running balance after deciding one character. While \(r = 1\) (blue) every ) forks into "delete" or "keep". Once the budget is spent (green) the path is forced: keep everything, and just check it stays valid.

19 calls in total. Deleting at index 1 gives (())(), and deleting at index 3 or 4 gives ()()() twice, which the set merges into 2 answers. The all-keep trunk dies at index 4 (balance \(-1\)), so the branch "delete the ) at 6" is never even generated.

Contrast: BFS by level

The other classic approach skips step 1. Level \(k\) holds every unique string with \(k\) characters deleted. Build each level from the previous one by deleting one paren in every possible spot, and stop at the first level that contains a valid string. It's correct because the first valid level is the minimum, but it pays for not knowing the budget up front. It generates and tests whole strings (6 unique one-deletion strings here, \(O(n)\) each), it can't prune a prefix early, and levels can grow to \(\binom{n}{k}\). The budgeted DFS only builds strings whose length is already right, and it kills bad prefixes as soon as they appear.

Code

class Solution:
    def removeInvalidParentheses(self, s: str) -> List[str]:
        # 1) Count the minimum removals: unmatched ')' (r) and leftover '(' (l).
        l = r = 0
        for c in s:
            if c == '(':
                l += 1
            elif c == ')':
                if l:
                    l -= 1
                else:
                    r += 1

        n = len(s)
        res = set()
        path = []

        # 2) DFS: at each paren either delete it (if budget allows) or keep it,
        #    never letting the running balance go negative.
        def dfs(i: int, l: int, r: int, bal: int) -> None:
            if bal < 0 or bal > n - i:
                return
            if i == n:
                if l == 0 and r == 0 and bal == 0:
                    res.add(''.join(path))
                return
            c = s[i]
            if c == '(' and l > 0:
                dfs(i + 1, l - 1, r, bal)
            elif c == ')' and r > 0:
                dfs(i + 1, l, r - 1, bal)
            path.append(c)
            if c == '(':
                dfs(i + 1, l, r, bal + 1)
            elif c == ')':
                dfs(i + 1, l, r, bal - 1)
            else:
                dfs(i + 1, l, r, bal)
            path.pop()

        dfs(0, l, r, 0)
        return list(res)

Complexity

Worst case \(O(2^{p} \cdot n)\) time for \(p \le 20\) parens (each paren is keep/delete, plus joining a leaf), but the exact budgets and the \(0 \le \text{bal} \le n-i\) window prune nearly all of it in practice. Space is \(O(n)\) recursion and path, plus the output set. Step 1 is the 921 counter word for word, and step 2 is the generate-with-counts backtracking of 22, run as deletions on a fixed string.
