3723. Maximize Sum of Squares of Digits

Greedy by convexity: pack 9s, then the remainder, then zeros

Insight

We pick \(num\) digits \(d_i \in [0, 9]\) with \(\sum_i d_i = sum\) and want to maximise

$$ \text{score} = \sum_i d_i^2 . $$

The square is convex, so spreading the total out is the worst thing you can do and concentrating it is the best. Exchange argument: take two digits \(a \ge b \ge 1\) with \(a < 9\). Moving one unit from \(b\) to \(a\) keeps the sum and changes the score by

$$ (a+1)^2 + (b-1)^2 - a^2 - b^2 = 2(a - b) + 2 > 0 . $$

So at the optimum at most one digit sits strictly between 0 and 9. That fixes the multiset: \(\lfloor sum/9 \rfloor\) nines, one digit \(sum \bmod 9\) if it's nonzero, and zeros for the rest.

The tie-break is free. Every max-score integer uses that same multiset, and writing it in descending order (9s, remainder, zeros) gives the largest number. The leading digit is never 0 because \(sum \ge 1\). The only infeasible case is \(sum > 9 \cdot num\).

Same sum, different spreads

Three ways to split a digit sum of 22 across 4 digits. Packing the 9s gives 9940 with score 178. The even spread 6655 only gets 122. Each step toward concentration raises the score, which is exactly the \(2(a-b)+2\) gain above.

Checked against every candidate

All 69 three-digit numbers whose digits sum to 13. The top score of 97 is reached by 409, 490, 904 and 940, which are the four valid orderings of {9, 4, 0}. Greedy writes them descending and lands on 940, the top-right point.

Code

class Solution:
    def maxSumOfSquares(self, num: int, sum: int) -> str:
        if sum > 9 * num:
            return ""
        nines, rem = divmod(sum, 9)
        digits = "9" * nines + (str(rem) if rem else "")
        return digits + "0" * (num - len(digits))

Complexity

\(O(num)\) time and space to build the string, which is the size of the output anyway.
