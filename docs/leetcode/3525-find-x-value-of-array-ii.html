3525. Find X Value of Array II

Segment tree: product + prefix remainder counts (tiny k)

When

Point updates + range queries that ask “how many non-empty prefixes of \(\mathrm{nums}[\mathrm{start}:]\) have product \(\equiv x\pmod k\)”, with \(k\le 5\), \(n\le 10^5\), \(q\le 2\cdot 10^4\). Recomputing the running product from \(\mathrm{start}\) each query is too slow; the modulus is tiny, so remainder counts fit in a segment node.

Move

Build a segment tree. Each node for a contiguous segment stores:

$$ \begin{aligned} \mathrm{prod} &= \Bigl(\prod_{\text{seg}} a_i\Bigr) \bmod k,\\ \mathrm{pref}[0..k-1] &= \text{counts of non-empty prefixes of that segment by product remainder}. \end{aligned} $$

Merge \(L\oplus R\): copy \(L.\mathrm{pref}\); for each remainder \(r\) with count \(c\) in \(R.\mathrm{pref}\), add \(c\) into \((L.\mathrm{prod}\cdot r)\bmod k\); set \(\mathrm{prod}\leftarrow (L.\mathrm{prod}\cdot R.\mathrm{prod})\bmod k\). Point-update a leaf and re-merge up. Answer a query by folding \([\mathrm{start},n-1]\) and reading \(\mathrm{pref}[x]\).

Visual

Example after the first update of sample 1: \(\mathrm{nums}=[1,2,2,4,5]\), \(k=3\), \(x=2\). Running prefix products mod 3; green cells are \(\equiv 2\) (answer \(2\)).

Prefixes of lengths 2 and 5 hit \(\equiv 2\). The histogram is exactly the \(\mathrm{pref}\) vector a root (or range fold) would store.

Why the merge works: a prefix that ends inside \(R\) is “all of \(L\)” times a relative prefix of \(R\), so every right remainder shifts by \(L.\mathrm{prod}\).

\(L=[1,2]\) and \(R=[2,4]\) merge to \([0,3,1]\) — matches the four prefixes of \([1,2,2,4]\).

Merge (pseudocode only)

def merge(L, R, k):
    out_pref = L.pref[:]          # start with left prefixes
    for r in range(k):
        c = R.pref[r]
        if c:
            out_pref[(L.prod * r) % k] += c
    return Node(prod=(L.prod * R.prod) % k, pref=out_pref)

# point update leaf → re-merge up
# query: fold nodes covering [start, n-1] → answer = fold.pref[x]
