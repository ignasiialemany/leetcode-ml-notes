2333. Minimum Sum of Squared Difference

Greedy water level: pool k1+k2, binary-search the cap on |d|

Insight

Only \(d_i = |a_i - b_i|\) matters, and a ±1 on nums1 or on nums2 both shrink some \(d_i\) by 1. So the two budgets merge into one, \(k = k_1 + k_2\). Lowering \(d\) by one saves \(d^2-(d-1)^2 = 2d-1\), which is largest for the largest \(d\). The greedy is always "hit the tallest bar", and doing that \(k\) times flattens the tops down to a common water level \(L\).

$$L = \min\Big\{\,L \ge 0 : \sum_i \max(0,\, d_i - L) \le k\Big\}$$

Find \(L\) by binary search (the cost is monotone in \(L\)). After capping everything at \(L\), the leftover \(r\) units are fewer than the number of bars sitting at \(L\), so \(r\) of them drop to \(L-1\). If \(\sum d_i \le k\) the answer is 0.

Flattening the tallest bars

Diffs 9, 7, 7, 5, 3, 2, 1 with \(k=8\). Cutting the red tops costs 4+2+2 = 8 exactly, so \(L=5\) with nothing left over and \(\sum d^2\) falls from 218 to 114.

Why greedy: convex, diminishing returns

Each extra unit saves \(2\max d - 1\), and that max only goes down, so the curve is convex. No exchange can beat always shaving the current maximum.

Code

class Solution:
    def minSumSquareDiff(self, nums1, nums2, k1, k2):
        d = [abs(a - b) for a, b in zip(nums1, nums2)]
        k = k1 + k2
        if sum(d) <= k:
            return 0
        lo, hi = 0, max(d)
        while lo < hi:                       # smallest affordable cap
            mid = (lo + hi) // 2
            if sum(x - mid for x in d if x > mid) <= k: hi = mid
            else: lo = mid + 1
        L = lo
        k -= sum(x - L for x in d if x > L)  # leftover < #bars at L
        cnt = sum(1 for x in d if x >= L)
        res = sum(x * x for x in d if x < L)
        return res + (cnt - k) * L * L + k * (L - 1) ** 2

Complexity

\(O(n \log \max d)\) time, \(O(n)\) space for the diffs (a counting-sort sweep over values ≤ 1e5 also works in \(O(n + \max d)\)).
